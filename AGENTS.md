# Popcorn: notes for coding agents

Popcorn is a Flutter movie and series streaming app (phones, iPad, Windows, Android TV). The app is in `flutter_client/`. Read this whole file before starting any task. These are decisions the owner has already made, so don't reopen them.

## Working with the owner

- **The owner is not technical.** Explain in plain language with everyday words. Say what changed and why before giving any detail. Keep file paths and jargon short and at the end. When they have to do something themselves, give numbered steps.
- **Questions are not instructions.** For a "can we…?" or "is it possible…?" question, investigate (reading code and measuring is fine), propose an approach with a recommendation, then **wait for a clear go-ahead** ("do it", "go with it") before editing code. Clear instructions ("remove it", "do the new release") mean act now.
- **Publish without asking.** Once a requested change is finished and checked, commit and push in the same turn and say it's live. Don't ask "should I publish?". An app release reaches every user, so always say clearly when you've done one.
- Be honest: if something is untested or only partly works, say so.
- **Don't fix twice (23 Nov 2026):** when a fix overlaps an approved to-do item, build the to-do version directly instead of patching something the to-do would later undo.
- **No AI co-author lines in commits** (no "Co-Authored-By: Claude" or similar) in this repo or popcorn-organization/popcorn. They make Claude show up as a contributor. (22 Nov 2026)
- Never commit secrets (`secrets.json`, `flutter_client/.env`, `android/key.properties`).
- **Keep this file up to date.** When the owner makes a new decision, gives a correction or says "always"/"never", add it to the right section of this file in plain words (with the date), commit and push it with the work. Change or remove rules here that turn out to be wrong. Don't add one-off details that only matter to the current task.

## Daily Sentry check (owner, 24 Nov 2026)

- **First thing each day, before the owner's request:** if `.git/sentry-last-check` (a local note, never committed) doesn't hold today's date, check Sentry first: `sentry issue list popcorn-02/popcorn --period 24h`, plus anything new or reopened since the last check, and how many devices opened the app (`sentry api "organizations/popcorn-02/sessions/?field=sum(session)&field=count_unique(user)&groupBy=release&statsPeriod=24h"`). Tell the owner in a few plain lines (new problems, how often, which platform and version, what you think the cause is), then write today's date (YYYY-MM-DD) into that file and carry on with their request. Don't fix anything found without the owner's go-ahead, unless it's part of what they asked for.
- **Fixed issues:** once a fix is in a release, resolve the issue in that release (`sentry issue resolve <ID> --in 'Popcorn@x.y.z+n'`; register the release first with `sentry api organizations/popcorn-02/releases/ --method POST` if Sentry hasn't seen it, and unresolve first if it was resolved in another release). Then Sentry reopens it if it happens again in that version or later. Never resolve or archive an issue that isn't fixed: ask the owner before ignoring one.

## Releases

- The public app and website live at **popcorn-organization/popcorn** (website: GitHub Pages from `docs/` on main, https://popcorn-organization.github.io/popcorn/).
- `.github/workflows/publish-release.yml` in this repo publishes a release **only when `version:` in `flutter_client/pubspec.yaml` changes** on main. To ship: bump the version and push. Never reuse a version number. The workflow also updates the README's latest line and `docs/flags.json` (Android and Windows).
- **Small and big updates (24 Nov 2026):** the version number decides. A new last number (4.5.3 → 4.5.4) is a small update: nobody is interrupted; Settings shows a card in the update screen's look ("A New Version Is Ready.", "See What's New") and the Settings button's own outline grows a small round bead at its top right, melted smoothly into it (one edge, coloured when Settings is open), with a dot in the mode's colour in it (plain dots looked stuck on; overlays left two edges; a bell shape was pointy); it stays until the update is installed (owner, 24 Nov 2026); that page (the update screen's look, with a back button) shows the notes and "Update Now". A new middle or first number (→ 4.6.0) also raises `min_required_version`: the full-screen update, now with the notes too. Pick the number by how big the change is; a fix for something serious (the app or the device stopping, e.g. a TV switching off) may go out as a big update so everyone gets it at once (owner, 24 Nov 2026). iPhones don't get the small-update card (TestFlight tells them). Notes scroll inside their own panel; the screen never scrolls.
- **Release notes (24 Nov 2026):** every release gets notes in `RELEASE_NOTES.md` (a `## x.y.z` heading at the top, `- ` lines in plain words for viewers, no technical terms) before the version bump. The workflow copies the newest five into flags.json (`release_notes`, `latest_version`) and the version's own onto its release page. Never name this source repo in them. Test the update pages with `--dart-define=UPDATE_TEST=small` or `big` (a pretend newer version with long notes; off in real builds).
- **Update flags (23 Nov 2026):** the app reads `https://popcorn-organization.github.io/popcorn/flags.json` (the public repo's `docs/flags.json`). This repo's `docs/flags.json` is an identical copy that app versions up to 4.4.1 still read. The release workflow updates this repo's copy and then copies it to the public repo, so this repo's is the master: make any change by hand (e.g. the iPhone flag) identically in both. Versions after 4.4.1 read the public one.
- iPhone: Codemagic (`codemagic.yaml`, `xcode: latest`) builds TestFlight. The workflow does **not** raise the iPhone flag (`ios.min_required_version` in flags.json). Raise it only when asked, after the Codemagic "iOS TestFlight Release" check on the release commit succeeds plus ~10 minutes for Apple processing.
- From April 2027 iOS uploads need the iOS 27 SDK (Xcode 27). Near then, check that Codemagic's "latest" has moved; if it hasn't, pin `xcode: 27.x`.

## Building and testing (Windows PC)

- Devices: the owner uses a **Galaxy S25 Ultra** daily (120 Hz, USB serial RFGYB1R4V2F). A **Galaxy S10** (60 Hz, OpenGLES) is on wireless adb for test installs and frame measurements. Its adb name changes between sessions, so run `adb devices` first.
- Android test install: `flutter build apk --release`, then `adb -s <serial> install -r <apk>`. Launch with `adb shell monkey -p com.popcorn.flutter_client -c android.intent.category.LAUNCHER 1`. A "prod build" on the S25 means this release build.
- Judge smoothness only on profile/release builds. Over ~16 ms per frame on the S10 will show on the S25.
- **One Popcorn at a time on Windows (24 Nov 2026):** opening it again brings the open window forward. A copy still closing is waited for (up to 10 s) and the new one then opens; a copy stuck before showing its window (seen on the owner's PC with 4.6.0: every click did nothing until it was ended in Task Manager) is ended once it's 20 s old, and the new one opens (`windows/runner/main.cpp`, release builds only). Each startup step has a 15 s limit; one that runs over is reported to Sentry as "Startup step … not done", so the cause shows up there.
- **Windows build:** close the running app (process `flutter_client`), then delete `windows/flutter/ephemeral`, `build/windows` and `.dart_tool/flutter_build`, then run `flutter build windows --release --dart-define-from-file=secrets.json` (~4–5 min). Deleting only the ephemeral folder makes it worse. Never build while the owner's own `flutter run` is going; two builds break each other. Testing an installed Windows release needs the installed Popcorn closed (single instance), so ask first and reopen it afterwards.
- Local builds need `--dart-define-from-file=secrets.json` for Google sync (`.\run` does this). The app has no built-in Gemini key.

## Product rules

- **Viewing experience (21 Nov 2026):** Use Netflix and the Apple TV app as references for how Popcorn should feel. Keep playback controls familiar, menus simple, and technical details out of the way. Use Popcorn's own visual design.
- **Movies and series only.** Hide documentaries, making-ofs/featurettes, stand-up specials, concert films, and talk/news/reality TV. Every list, row, recommendation and Ask result goes through `TMDBService.isUnsuitable`. Real musicals, comedies and sitcoms stay.
- **Finished titles (23 Nov 2026):** a title counts as watched from the end credits' start, or 95% of the way when the credits aren't known. On closing a watched movie, or a series' latest episode that's out, it leaves Continue Watching (as on Netflix) and its download is deleted. A watched episode with a next one out moves Continue Watching on to that episode and drops only its own file's data. A season finale whose next season couldn't be looked up is left alone. A series that left this way waits for its next episode: about once a day per show (after start-up, in the background) the app asks TMDB, and once that episode has aired the series comes back to Continue Watching at it with no progress (watching the series again ends the wait; the waiting list syncs through Google Drive, up to 50 shows, kept 2 years).
- **Continue Watching's play button (24 Nov 2026):** no popup while it starts: the button gets a loading ring (pressing it again gives up); only a failure is said. Users don't need to know what happens in the background.
- **Never switch audio language.** Never play a different language than the one chosen: no fallback to a dub, not even with a notice. Every automatic copy choice (start fallback, stall recovery, next episode, resume) must filter to the chosen language. If nothing in that language works, stop and say so.
- **Streaming-service buttons ("watch on Netflix" etc.)** open only that service's app, directly to the title (`LaunchMode.externalNonBrowserApplication`). Never fall back to TMDB, a search page or any website. If it can't open, show a message.
- **Books and Music are switched off** on every platform (`AppModeService.booksAndMusic = false`). Don't advertise them.
- **Ramen** = anime mode (phones, iPad, Windows; colour #FD5602). Anime is blocked from Popcorn there (`TMDBService.isAnime`). TV has no mode switch and keeps anime in Popcorn. Never use fan edits (e.g. One Pace). Episode numbers go through EpisodeNumbering (Cinemeta) before Torrentio.
- **Ratings:** the title page shows the IMDb rating from Cinemeta. Home, trending and search lists are still TMDB, so don't claim they come from IMDb.
- **Lists of titles:** use dense poster grids, not side-scrolling carousels. Ask before replacing a grid with rows.
- **Plain glass = solid black.** On slow devices, battery saver and all TVs, every overlay is opaque AMOLED black (the Ask/Search text bar is dark grey, `glassFieldTint`). New glass surfaces must use `glassTint(context)` / `glassSheetTint(context)` (glass_blur.dart), not `kGlassTint` directly.
- **Ask and Search text bar (23 Nov 2026):** both use the same bar (`lib/widgets/glass_text_bar.dart`). Ask's round button is New chat; Search's is an ✕ that clears the text and only shows while there's text (it grows out of the bar). The line that runs round the bar is in each tab's own colours (Ask: the app's pastels; Search: its purple glow) and plays only the first time that tab is opened after the app starts. Each time Search or Ask is opened, the field is selected with the keyboard up, but only while its page is the one on screen: never under a title page or the player (a phone turned sideways can be over 800 wide, so the tabs are rebuilt in the wide layout's column behind the player; that raised the keyboard over the film, 24 Nov 2026) (phones: keyboard; Windows: cursor in the field; TV: on-screen keyboard, Back closes it and the arrows then leave the field).
- **Home hero slideshow** (top 10 trending, Ramen top 10 popular, `lib/widgets/hero_carousel.dart`): keep the easeInOutCubic 800 ms slide, 7 s per slide. Text, buttons and picture frames move exactly with the finger; only the image inside moves at half speed. On TV the remote never changes slides. No "#N Trending This Week" line under the logo on any device, so the logo sits lower (owner, 24 Nov 2026).
- **Top of pages (24 Nov 2026):** the tab pages' titles get a frosted island once scrolled. The Home logo has no island: it scrolls up and away with the page (owner, 24 Nov 2026), whole, passing under the phone's status bar (clock and icons) like the page; never faded or cut off at the status bar's edge (owner, 24 Nov 2026). A dark gradient from the top instead (whole bar, then top-left corner) was tried and rejected by the owner.
- **Tab glow (24 Nov 2026):** one glow per mode, made from the mode's colour (Popcorn cream, Ramen orange), on Search, My List and Settings (and Settings' own pages); Ask keeps its own. Switching between those tabs the glow stays still (no bloom, no dip); only the content fades. It blooms only when arriving from Home or Ask.
- **Wide window (24 Nov 2026):** the side panel's pages have 16 on all four sides. The Ask button shows the Ask logo (icon and "ask", as on the Ask page and website). The Home loading shimmer fills the whole window, with no placeholder cards.
- **Continue Watching card menu (23 Nov 2026):** no confirm box. Long-press (phones, iPad) or right-click (Windows; long-press does nothing there) lifts the card in place, dims and blurs the rest (plain glass: dim only) and opens a small glass menu under it (above if no room): "More Info" and a red "Remove from Continue Watching". Remove happens at once with "Removed <title>" and Undo for 5 s; Undo restores progress, episode and episode progress and syncs as a new change. TV has no menu (its card keeps its own buttons). Built as `showCardMenu` (`lib/widgets/card_menu.dart`).
- **Subtitles (23 Nov 2026, Netflix style):** One button per language; filenames hidden; no “Try another subtitle”. The app picks the copy in that language and swaps to a better one by itself (one made for the file, or one whose timing is confirmed). Timing is automatic; never offer manual timing controls. Keep timing messages inside the panel and leave the player buttons steady. The chosen language's row has a sync icon button: it turns while syncing (no “Checking the timing…” text) and, pressed, re-checks that subtitle and the language's other copies against the sound already heard, keeping the current subtitles on screen meanwhile (owner, 23 Nov 2026). Only show subtitles whose timing is known (built in, made for the file, retimed against a subtitle that fits, or confirmed by listening); until then show a quiet grey shimmering bar where the subtitles go, saying “Syncing subtitles…” (or “සිංහල උපසිරැසි සකසමින්…” in Sinhala while Sinhala for the scene is generated); it appears after 3 s, its words as big as the subtitles on every device, and stays while paused (owner, 24 Nov 2026). Subtitles stay on screen while paused too (owner, 24 Nov 2026). With the controls up (a menu open included) the subtitles and that bar sit above the progress bar, never under it (owner, 24 Nov 2026). No bright or coloured placeholder blocks (owner, 23 Nov 2026: too much highlighting). Listening is confirmed when two separate stretches of dialogue agree within 0.4 s, sure or not on their own. Never give up checking; if no copy fits, say so in the panel and keep checking quietly. A fingerprint (hash) match named for a cinema copy (CAM/TS) while the video is a web or disc copy is not trusted; listening decides (Street Fighter, 23 Nov 2026: its hash-matched TELESYNC subtitle didn't fit; the release-named one did). When subtitles are on, picking a copy prefers, among well-shared copies of the same quality (after audio language and the TV picture check, before episode-or-pack), one with subtitles built in, in the viewer's subtitle language: first one seen to have them when played before, then one whose name says so (ESub for English; MSubs/Multi-Subs for any language; "English Subs", "Sub Ita"; bare "Subs" counts as English); it never refuses a copy (`BuiltInSubtitles`, 23 Nov 2026).
- **Sinhala subtitles:** auto-translated from English subtitles with the person's own Gemini key (Settings). Keep the model order and the spoken-Sinhala instructions in the translator. Where the English line is on two lines and Gemini joined the Sinhala into one, the app puts the break back (two speakers at the second dash; a long sentence near its middle; short lines stay whole: SubtitleTranslator.restoreBreaks, 24 Nov 2026). Sinhala is made from the English copy already in time (and moves to one that becomes in time), so it takes that timing at once instead of being listened for (owner, 24 Nov 2026). When the video has its own subtitles in that language, the player follows them quietly in the background (mpv secondary subtitle, never drawn: the player draws only the main subtitles itself, _OwnSubtitleView) and times the downloaded copies by matching their lines (SubtitleLineMatch, two lines agreeing within 0.4 s); no extra download, seconds instead of minutes (The Mentalist, 24 Nov 2026). That timing is the surest: other languages' subtitles never retime a copy in a language the video has built in, and listening never overrides it; the sync button checks against them again too (The Mentalist S1E6, 24 Nov 2026: Portuguese/Bosnian subtitles shifted the Sinhala 1.2 s out). Going back to Sinhala reloads its file, so lines made meanwhile show at once. Sinhala subtitles (and the Sinhala "making" note) are drawn at 0.8 of the English size: Noto Sans Sinhala draws much bigger at the same size (owner, 24 Nov 2026). Without a key the option stays visible but greyed out ("Add your Gemini key in Settings"). The owner prefers greying things out to hiding them.
- **No Gemini-translated English subtitles (22 Nov 2026):** never make English (or other-language) subtitles by translating another language's subtitles with Gemini, not even as a last resort. Sinhala is the only translated option.
- **Sync (Google Drive appDataFolder, no server):** lists belong to the Google account. Sign in / Sign out (no switch). Signing out saves first, then clears local lists. "Delete synced data" only deletes data and never signs anyone out. Signing out never revokes Google's grant. Confirmed subtitle timings (per copy and subtitle, `SubtitleTimingStore`, newest 500 kept) sync too, so the phone, TV and PC share them (23 Nov 2026). No popups in Settings: Sync and Gemini key are their own pages (owner, 24 Nov 2026: keep them as two rows; no combined "Google" page and no Google "G" logo). Tests: `test/sync_merge_test.dart`, `test/sync_flow_test.dart`, `test/subtitle_timing_store_test.dart`. When it checks (24 Nov 2026): at start, on switching to Home/My List/Settings, on coming back to Home from the player or a title page, when the app returns to the screen (incl. a Windows window regaining focus) after a minute away, and on TVs and computers every 5 minutes while on screen.
- **Never** disguise traffic to use YouTube/Netflix "unlimited" data packages.
- **Crash reports (24 Nov 2026):** Sentry (organisation `popcorn-02`, project `popcorn`, EU storage; `lib/services/crash_reports.dart`), release builds only. Always on: Settings → Privacy shows "Send crash reports" as a greyed-out switch that's on and can't be turned off (owner's choice). Crashes and freezes only: no speed tracing, screenshots or screen recordings. Before sending, links, keys, tokens, e-mail addresses and the Windows user name are removed; Sentry doesn't store IP addresses. Network drop-outs aren't reported, and each run sends each error once (25 at most), to stay within the free plan (5,000 a month). The DSN is in the code (it can only send reports, not read them). The `sentry` command on the PC is signed in to the owner's account (`sentry issue list popcorn-02/popcorn`).

## TV app (Android TV / Google TV / Fire TV only, no Apple TV)

- Same layout as Windows, laid out at 1280 wide and scaled. Popcorn only (no mode picker).
- Gemini key is added from a phone via QR code (PhoneKeyServer).
- **Player remote:** controls appear ONLY when OK is pressed. OK shows them without pausing, with the play button selected (Netflix style). Left/right skip 10 s showing only the skip icon. Up/down do nothing while controls are hidden. A slow seek shows a centred spinner, not the controls. TV subtitles are 40% bigger.
- Continue Watching cards on TV have an "i" (info) button before play.
- **Weak TVs (24 Nov 2026):** the app reads the TV's memory at start (`TvDevice.isLowMemory`: 2 GB or less, Android's low-RAM flag, or ≤128 MB per app). A tester's Panasonic (2KTV-3MH, Android TV 14, ~1.5 GB) switched itself off scrolling Search and a title page on 4.5.2. Weak TVs get lighter pictures: a 40 MB picture store (not 100), w1280 backgrounds, w780 logos/posters/stills, h632 photos, posters decoded at drawn size, and the Home slideshow held while another tab is open. TVs with more memory keep everything at full quality (an HD TV still skips 4K backgrounds and original logos it can't show). Phones, iPad and Windows are unchanged. Try it on any device with `--dart-define=LOW_MEMORY_TEST=true` (never in real builds). Not yet confirmed on the tester's TV.
- **TV picture (23 Nov 2026):** TVs prefer a copy that isn't Dolby-Vision-only (name says DV/DoVi/Dolby Vision with no HDR, HDR10, HDR10+ or HLG), because such copies show purple/green colours there. It is only a preference within the same quality among well-shared copies (`StreamResolver.pictureRank`); a Dolby-Vision-only copy still plays when it's the only good one. Phones, iPad and Windows are unchanged. Debanding for TVs (`_debandOnTv` in `player/streaming.dart`) is built but OFF: on the S10 it cost nothing (0 dropped frames, 23 Nov 2026), but cheap TVs (e.g. Panasonic TH-32MS670N: 4× Cortex-A53 1.5 GHz, 1.5 GB) are far slower. Turn it on only after a tester tries a build with it on a real TV.
